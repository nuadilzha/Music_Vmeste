# Музыка вместе

Многопользовательский MVP для поиска музыкантов, групп и специалистов. React + TypeScript + Vite на клиенте, Node.js и SQLite на сервере. Данные и файлы сохраняются на диске; внешняя база не нужна.

## Быстрый запуск

Требуются **Node.js 24+** и npm.

```sh
npm ci
npm run dev
```

Откройте **http://localhost:3000**. Vite работает на порту 3000, API — на 3001. Оба процесса запускаются одной командой. Клиент обновляется через HMR, сервер — через Node watch. Остановка: `Ctrl+C`.

Создайте аккаунт в интерфейсе. Предустановленных паролей нет. Для проверки переписки зарегистрируйте второй аккаунт в другом браузере или приватном окне: откройте профиль первого участника и нажмите «Написать».

## Возможности

- Регистрация, вход и выход; сессии действуют семь дней.
- Профили музыкантов и специалистов: описание, город, жанры, роль, опыт, навыки, доступность, ссылки, фото и обложка.
- Портфолио: загрузка изображений, аудио и видео, прямые ссылки, просмотр и воспроизведение. До 12 работ, до 8 МБ на файл и 100 МБ файлов на аккаунт.
- Поиск по тексту, городу, жанру и роли; категории и фильтр реальных участников. Параметры поиска сохраняются в URL.
- Избранное для профилей и групп, отдельное для каждого аккаунта.
- Создание, редактирование и удаление групп: состав, вакансии, репетиции, условия и портфолио. Управляет создатель группы; состав — текстовый список, без приглашений.
- Объявления: создание, редактирование, удаление, фильтры и отклики через личные сообщения.
- Общая лента: публикации, теги, фильтрация и удаление своих записей. Обновляется кнопкой или при возвращении в окно.
- Приватные переписки между зарегистрированными участниками, обновление каждые четыре секунды и повтор подключения при временной ошибке.
- Мобильное меню, состояния загрузки, уведомления об ошибках и страницы 404.

Карточки с отметкой **«Пример»** — демонстрационные данные. Их нельзя редактировать или использовать как получателей сообщений. Статистика считает только реальные записи. Демо-медиа загружаются с внешних источников; собственные загрузки хранятся локально. Для медиа-ссылок нужен прямой адрес файла, а не страница YouTube или SoundCloud.

## Проверки

```sh
npm run typecheck
npm test
npm run build
npm run format:check
```

Серверные тесты проверяют авторизацию, права владельца, валидацию, Origin, загрузки и диапазоны байтов, избранное, приватность сообщений и сохранение после перезапуска. Интеграционные тесты выполняют действия через React-формы в jsdom с настоящим API и временной SQLite-базой. Тестовые аккаунты и файлы не попадают в рабочую базу. jsdom не заменяет визуальную проверку в настоящем браузере.

GitHub Actions выполняет проверки на Windows и Linux. `npm run format` форматирует исходники.

Если сайт открывается пустым, выполните `npm ls --depth=0`. При отсутствующих зависимостях остановите проект, выполните `npm ci`, затем снова `npm run dev`. Для проверки уже запущенного проекта выполните `npm run build` и `npm run smoke`: проверка загружает клиентские модули и запускает собранный React-клиент с действующим API в jsdom. После восстановления зависимостей обновите страницу через `Ctrl+F5`.

## Собранная версия

```sh
npm run build
npm start
```

Откройте **http://localhost:3001**. Сервер обслуживает API, файлы и клиент, включая прямые ссылки на внутренние страницы. `npm run preview` запускает тот же сервер.

Скопируйте `.env.example` в `.env`, если нужны настройки. Команды запуска автоматически читают `.env`.

| Переменная      | По умолчанию   | Назначение                                                                          |
| --------------- | -------------- | ----------------------------------------------------------------------------------- |
| `PORT`          | `3001`         | Порт сервера; в разработке не используйте порт Vite 3000                            |
| `HOST`          | `127.0.0.1`    | Адрес прослушивания                                                                 |
| `APP_ORIGIN`    | Origin запроса | Точный публичный Origin, например `https://music.example.com`, без завершающего `/` |
| `COOKIE_SECURE` | `false`        | `true` для HTTPS-развёртывания                                                      |

Для публикации нужен сервер с постоянным диском и Node.js 24. Настройте HTTPS через reverse proxy, `APP_ORIGIN` и `COOKIE_SECURE=true`. Проксируйте весь сайт, включая `/api` и `/uploads`, на порт 3001. Лимит тела запроса на proxy — не меньше 12 МБ. За proxy оставьте `HOST=127.0.0.1`. Приложение рассчитано на один экземпляр сервера; статический хостинг без Node.js не подходит.

## Docker

```sh
docker build -t music-vmeste .
docker run --name music-vmeste -p 127.0.0.1:3001:3001 -v music-data:/app/data -v music-uploads:/app/uploads music-vmeste
```

Для публичного HTTPS-домена передайте `-e APP_ORIGIN=https://ваш-домен -e COOKIE_SECURE=true` и подключите reverse proxy. Именованные тома сохраняют данные при пересоздании контейнера. Docker-конфигурация подготовлена; её нужно проверить на машине с установленным Docker.

## Данные и резервные копии

- `data/music.sqlite` — аккаунты, хеши паролей, сессии, профили, группы, объявления, публикации, избранное, сообщения и метаданные файлов.
- `uploads/` — медиа. Они публичны для портфолио; приватные документы здесь не храните.
- `server/seed.json` — примеры, добавляемые без перезаписи пользовательских данных.
- `dist/` — клиентская сборка; её можно пересоздать.

Для согласованной резервной копии остановите сервер и скопируйте **обе папки `data/` и `uploads/`**. Восстанавливайте их вместе. Не удаляйте их при обновлении кода. SQLite использует WAL: копирование только основного файла работающей базы может пропустить последние изменения.

Удалённые из сохранённого профиля или группы файлы очищаются, если больше не используются другой записью владельца. Файлы из несохранённых черновиков пока остаются и учитываются в квоте.

## Архитектура и границы MVP

`server/app.mjs` содержит HTTP API, проверку доступа, файловое хранилище и SQLite. `server/index.mjs` запускает сервер. `src/lib/api.tsx` отвечает за данные, сессию и уведомления. `src/components/` содержит общие элементы, `src/pages/` — пользовательские сценарии.

Пароли хешируются через scrypt с индивидуальной солью. Сессии используют случайные токены; в базе хранятся только их хеши. Cookie — HttpOnly и SameSite=Lax. Сервер проверяет Origin изменений, владельцев записей, поля, ссылки, форматы и размеры файлов. Есть ограничения частоты входа, публикаций, сообщений и загрузок. API не возвращает пароли, токены или чужие сообщения.

MVP рассчитан на небольшой пилот. Пока отсутствуют подтверждение email и восстановление пароля, администраторская модерация и жалобы, уведомления вне сайта, приглашения в группы, пагинация больших каталогов и горизонтальное масштабирование. Эти возможности следует добавить перед открытым массовым запуском.
